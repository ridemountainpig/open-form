Vercel runs your project as static files plus a function: the built forms and
Studio are served as they are, and one function answers the API and the pages.
Functions have no persistent disk, so responses go to
[Postgres](/docs/deploy/postgres): Neon or Supabase both work.

This is the same project `open-form dev` runs: forms at `/f/<id>`, Studio at
`/studio`. To render forms inside a Next.js app you already have instead, see
[Next.js](/docs/deploy/nextjs).

<Steps>
<Step>

### Add the function

Starting a new project? `open-form init --vercel` (or answering yes to
**Deploy to Vercel?** after picking Postgres) writes both files below and adds
`pg`, so you can skip to the database.

```npm
npm create open-form@latest my-forms -- --vercel
```

For an existing project, install the Postgres driver:

```npm
npm install pg
```

Add two files at the root of the project, next to `forms/`:

```ts title="api/index.ts"
import { createOpenFormApp } from '@open-form-build/core/vercel';

export default createOpenFormApp();
```

```json title="vercel.json"
{
  "$schema": "https://openapi.vercel.sh/vercel.json",
  "framework": null,
  "buildCommand": "open-form build",
  "outputDirectory": "dist/client",
  "functions": {
    "api/index.ts": { "includeFiles": "dist/**" }
  },
  "routes": [
    { "src": "/(index\\.html)?", "dest": "/api" },
    { "handle": "filesystem" },
    { "src": "/(.*)", "dest": "/api" }
  ]
}
```

Vercel serves the built assets from `dist/client`, and every other path goes
to the function. The function reads the server bundle from
`dist/server/entry.js` by path, so `includeFiles` ships it along.

</Step>
<Step>

### Create the database

<Tabs items={['Neon', 'Supabase']}>
<Tab value="Neon">

The quickest way: add Neon from the Vercel Marketplace (**Storage → Create
Database**) and connect it to the project. Neon then sets `POSTGRES_URL` (and
`DATABASE_URL`) in the project, and the function uses it whenever
`OPEN_FORM_DATABASE_URL` isn't set, so there's nothing to copy.

Otherwise, create a project in [Neon](https://neon.tech) and copy the
**pooled** connection string (its host has `-pooler` in it). It looks like:

```text
postgres://user:password@ep-cool-name-123456-pooler.us-east-2.aws.neon.tech/neondb?sslmode=require
```

Neon's certificates come from a public authority, so `sslmode=require` verifies
them as is. Change it to `sslmode=verify-full` to say so outright and to
silence `pg`'s notice about `require`.

</Tab>
<Tab value="Supabase">

Create a project in [Supabase](https://supabase.com). Under **Connect**, copy
the **Transaction pooler** connection string (port 6543), the one meant for
serverless functions:

```text
postgres://postgres.abcdefghijklmnop:password@aws-0-us-east-1.pooler.supabase.com:6543/postgres
```

Supabase signs its certificates with its own authority, so verifying them
needs its certificate. Download it from **Database settings → SSL
configuration**, commit it to your project (it is public, not a secret), point
the connection string at it, and ship it with the function:

```text
…:6543/postgres?sslmode=verify-full&sslrootcert=./supabase-ca.crt
```

```json title="vercel.json"
"functions": {
  "api/index.ts": { "includeFiles": "{dist/**,supabase-ca.crt}" }
}
```

The Supabase integration in the Vercel Marketplace also sets `POSTGRES_URL`,
but without the certificate it can't be verified, so set
`OPEN_FORM_DATABASE_URL` as above anyway; it wins over `POSTGRES_URL`.

Open Form keeps its tables in the `open_form` schema. Supabase's table editor
shows `public` by default; pick `open_form` there to browse responses.

</Tab>
</Tabs>

</Step>
<Step>

### Set the environment variables

In the Vercel project's **Settings → Environment Variables**:

| Variable | Value |
| --- | --- |
| `OPEN_FORM_DATABASE_URL` | The connection string from the last step. Leave it out when the Marketplace set `POSTGRES_URL` or `DATABASE_URL` for you; when it's set, it wins. |
| `OPEN_FORM_SECRET` | At least 16 random characters, the same on every deploy. Functions can't write the generated secret file. |
| `OPEN_FORM_ADMIN_PASSWORD` | Turns on Studio and the admin API. Without it, `/studio` answers 404 unless `studio.public` is `'read-only'`. |

Generate the secret with:

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

You don't need `OPEN_FORM_TRUST_PROXY`: the function counts rate limits by the
address Vercel puts last in `X-Forwarded-For`.

For local development, `open-form dev` keeps using SQLite in `.open-form/`
unless `.env` sets `OPEN_FORM_DATABASE_URL`. A separate database (or Neon
branch) for development keeps test responses out of production.

</Step>
<Step>

### Deploy

Push to a Git repository connected to Vercel, or run `vercel deploy`. The first
request creates the tables. Forms are at `https://<your-app>.vercel.app/f/<id>`
and Studio at `/studio`.

To check the production database from your machine, run
[`open-form db status`](/docs/cli/db) with its connection string in the
environment:

```bash
OPEN_FORM_DATABASE_URL='postgres://…' npx open-form db status
```

</Step>
</Steps>

## Webhooks

A function stops once it has answered, so a [webhook](/docs/deploy/webhooks)
delivery still in flight is cut off. Install `@vercel/functions` and pass its
`waitUntil` to keep it alive:

```ts title="api/index.ts"
import { waitUntil } from '@vercel/functions';
import { createOpenFormApp } from '@open-form-build/core/vercel';

export default createOpenFormApp({ waitUntil });
```

Retries that come minutes later outlast the function and are lost.

## Setup errors

The function sets itself up on its first request. A missing build, a SQLite
database it can't open (no `OPEN_FORM_DATABASE_URL`, `POSTGRES_URL` or
`DATABASE_URL`), a secret it can't
create (no `OPEN_FORM_SECRET`), or an admin password that breaks the
[rules](/docs/deploy/production) makes that fail, and every request then
answers 500 with the reason in the function logs.
